Key Concepts

Seven ideas that explain most of how HTTP works.

1. Client and Server

HTTP has two roles. The client sends requests and the server answers them. The client always speaks first, and a server never sends a page to a browser that didn't ask for one.

Example: Chrome on your laptop is the client. The computer hosting the KSU website is the server.

2. Request and Response

Every HTTP exchange is one request followed by one response. The request says what the client wants. The response says whether it worked and includes the content. Loading one page usually takes many of these exchanges, one for each file.

Example: the browser requests /index.html, reads it, then sends separate requests for styles.css and each image on the page.

3. HTTP Methods

The method is the verb at the start of a request. GET reads something, POST sends data, PUT replaces something, DELETE removes it, and HEAD asks for just the headers. Methods that only read are considered "safe" because they don't change anything on the server.

Example: viewing a post is a GET. Writing a comment on it is a POST.

4. Status Codes

Every response starts with a three-digit status code. The first digit gives the category: 1xx informational, 2xx success, 3xx redirect, 4xx client error and 5xx server error.

  • 200 OK – the request worked
  • 301 Moved Permanently – the page has a new address
  • 404 Not Found – the server is fine, but nothing is at that address
  • 500 Internal Server Error – something broke on the server side

Example: typing http:// instead of https:// for many sites returns a 301 that sends you to the secure version.

5. HTTP Headers

Headers are Name: value lines that carry information about a message, like what type of content it is or how long it can be cached. Because new headers can be added without changing the protocol, headers are how most new HTTP features were added over the years.

Example: Content-Type: text/html tells the browser to show the response as a web page instead of downloading it.

6. HTTPS and TLS

Plain HTTP is sent as readable text, so anyone on the path, like someone on the same public Wi-Fi, can read or change it. HTTPS is the same HTTP sent through an encrypted TLS connection. It uses port 443 instead of port 80, and the server proves who it is with a certificate from a certificate authority.

HTTPS doesn't change any methods, headers or status codes. The request is identical. It is just placed inside an encrypted tunnel before it leaves your device.

Example: the padlock in your browser's address bar means the page was loaded over HTTPS. Plain http:// pages are marked "Not secure."

7. Stateless Communication

HTTP is stateless, meaning the server doesn't remember previous requests. Each request has to carry everything needed to answer it. This keeps servers simple and lets any one of many identical servers handle your next request.

Websites "remember" you by using cookies, which are just headers:

  1. You log in and the browser sends your username and password with a POST request.
  2. The server replies with a Set-Cookie header.
  3. The browser stores the cookie for that site.
  4. Every later request to that site includes a Cookie header, so the server recognizes you.

Example: your shopping cart staying full as you click around a store is done with cookies, not by HTTP itself.
